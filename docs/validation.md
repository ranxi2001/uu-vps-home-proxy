# 验证记录与边界

## 自动化验证

测试使用文档保留地址与隔离 Linux 网络命名空间，不访问真实家宽认证或付费模型。

- URL 解析、认证字符编码、TLS 证书验证配置与私有文件权限。
- 独立安装到含空格路径、重复升级、从任意目录运行命令。
- 当前 sing-box 内核实际配置检查。
- 目标 UID 无 TUN 时不能普通直连，其他 UID 可继续使用物理出口。
- UU UDP 套接字例外与连接标记保留。
- 控制服务器 IP 例外不放行普通浏览器的公共 STUN UDP。
- 两个私有命名空间之间复现：先按 UID 选择 TUN 源地址、再 OUTPUT 放行时，对端收到私网源地址，回包失败。
- 对这些控制数据包做源地址转换后，UDP 往返正常。
- 在 TUN 捕获之前为已有 UDP 端口配置直连策略时，可保留原源地址并正常往返。

运行：

```bash
python3 -m unittest discover -v
sudo env UU_VPS_INTEGRATION=1 python3 -m unittest discover -v
```

## 现场确认

2026-10-17，在 Linux VPS 的现有桌面用户上使用同等网络规则完成验证：普通 Chrome 的实际出口为指定代理；无代理参数的用户请求、TCP/UDP DNS 和 TLS 正常；用户之外的出口保持原状。UU UDP 远程桌面画面和鼠标操作由用户确认正常。真实地址、密码、登录状态及桌面内容不存入本仓库。

本次独立仓库整理不自动重命名、迁移或重启现场服务，保持已验收连接。

## 实际边界

- 这是网络路由管理，不是恶意代码沙箱；回环、本机 IPC 及受信任服务有其独立边界。
- UU 服务及其服务组内子工具属于直连例外；从 UU 内置远程终端启动的程序可能继承例外，应在桌面普通终端启动需代理的应用。
- DNS 重定向覆盖目标 UID 发出的 TCP/UDP 53。经 D-Bus 委托给其他 UID 的系统解析器需要独立验证。
- 上游不支持的 UDP 不改为普通直连。普通 IPv6 出站阻断。
- 时区按第三方地理库结果设置，仅对新进程生效；已打开的浏览器需要重开。
- 没有自动执行 Claude 订阅登录、模型调用或其他账号授权。
